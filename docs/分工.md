# v0.1 MVP · 五人分工

> 依据《教培工作台-思路整理.md》第 10 节的 v0.1 边界。验收标准只有一条：
> **做出一份《4.2 导数的综合应用》讲义，学生版 + 教师版两个 PDF，你自己看了愿意把它发给一个真实家长。**

---

## 一句话分工

| | 谁 | 一句话 |
|---|---|---|
| **A** | 后端与集成 | 定好五个人共用的文件格式，写那个只管读写文件的百来行小后端，把 53 的目录扫成知识点树，并守住主分支随时能跑。 |
| **B** | 前端 | 写老师日常用的那个本地网页：选知识点、填下单表单、看讲义列表、预览印出来的 PDF。 |
| **C** | Word 转换 | 把 Word 里的题目、公式和插图原样搬成 LaTeX，一个字都不许错。 |
| **D** | PDF 识别 | 把没有文字层的扫描版精讲册认成文字，整理进素材库——最容易卡住的一环，所以第一天就得开工。 |
| **E** | 模板与出稿 | 做 LaTeX 讲义模板和编译脚本，写那份给 AI 的作业流程说明书，最后 PDF 好不好看由他负责。 |

## 0. 契约先行（Day 0，全员半天）

这个架构最大的红利是**磁盘是唯一真相**——五个人之间的每一条接缝都是文件格式，不是函数调用。所以只要第一天把三个格式定死，五个人可以完全并行，谁都不用等谁。

必须当天定死并提交进仓库的三个契约：

| 契约 | 文件 | 谁依赖它 |
|---|---|---|
| 知识点树 schema | `knowledge-tree.yaml` | 全员 |
| 任务单 schema | `handouts/*/spec.yaml` | B 写它，E 读它 |
| kb 目录结构与文件名 | `kb/<学科>/<专题>/<小节>/` | C、D 写它，E 读它 |

设计文档 4.1 / 4.2 / 第 3 节已经给了草案，**直接固化，不要重新讨论**。

**定完立刻做一件事：每人手工捏一份自己的 fixture**（假的 kb 目录、假的 spec.yaml、假的 tex 片段），当天开始就拿假文件跑自己的部分。**任何人都不许说"我在等上游"**——上游是文件，假文件也是文件。

## 1. 五个角色

### A · 契约与集成（后端 + 知识点树）

**拥有**：`knowledge-tree.yaml`、`scripts/build_tree.py`、`app/server/`、仓库规范

- `build_tree.py`：扫 `【五三】26数学北京版/` 目录 → 生成 12 专题的**前两层全建**（第三层标签只填导数专题）
- Express 8 个接口（设计文档 9.2 已列全），只做列目录、读写文件、存图片、吐 PDF，**不承担任何计算**
- Python 脚本由后端 `spawn` 调用，后端不换成 Python
- 守 main 分支：保证 main 永远能跑、能编译
- 集成日负责把五个人的东西串起来

**需要**：Node/TS 基础 + Python 基础
**特点**：五个人里**最需要沟通、最不需要写代码**的角色。接口一共百来行，但契约定歪了五个人一起返工。

---

### B · 前端

**拥有**：`app/client/`（Vite + Vue 3 + TypeScript）

- 知识点树选择器（二层，强制）
- 标签多选，可新建（写回全局标签池）
- spec 下单表单：题源勾选（kb / docx / 我的材料）、受众、篇幅、模板
- 讲义列表：读 `/api/handouts`，显示 draft → outlined → compiled → delivered
- PDF 预览：`<iframe>` + 浏览器内置阅读器，学生版 / 教师版切换（**不要引 pdf.js**）
- 素材图上传
- 「复制为 prompt」按钮（备胎，不是主路）

**需要**：Vue 3 + TS
**特点**：**工作量最大、风险最低**，可以最晚合流，但不要最晚开工。

**两条红线**：
1. **前端不拼 prompt。** 它唯一写入的东西是 `spec.yaml`，prompt 模板全部留在 skill 里。
2. **只做讲义一个分区，其他分区连入口都不出现。** 别摆空壳——壳的形状由"模块之间共享什么"决定，只有一个模块时你看不出该共享什么。

---

### C · 确定性链路（docx → LaTeX）

**拥有**：`scripts/ingest_docx.py`、`scripts/html_table_to_latex.py`

- 装 pandoc，跑通 OMML → LaTeX（实测 334 个公式）
- 图片从 docx 解压 `word/media/*` 直接取，原始分辨率
- 两个 docx 源都要过：`5_习题WORD`、`6_10年高考真题分类题组`（68000 字，含「方法」21 处、「注意」12 处 → 按第 6 节映射到盒子环境）
- `html_table_to_latex.py`：MinerU 的表格 HTML → `tabular`（服务 D 的链路，但技能栈和 C 一致，放这里）

**需要**：Python + 基本 LaTeX 常识
**红线**：**逐字保真，AI 不碰题干。** 有 docx 还让 AI 重新识别题干，等于主动把确定性数据降级成识别结果——`x³` 抄成 `x²`、题源标错，印在发出去的讲义上你没法逐题核对。

---

### D · 识别链路（精讲册 PDF → kb）

**拥有**：`scripts/ingest_pdf.py`、`kb/` 落盘规范、`source.json` 溯源

- **第一天就开始装 MinerU**——这是整个项目最不确定的一块
- 四类分处理（设计文档 5.2）：`text` 交给 AI 重写要点 / `equation` 直接用 MinerU 的 LaTeX / `table` 交给 C 的脚本 / `image` 直接用切好的文件
- **行内公式要读 `middle.json` 的 span 层**，`content_list.json` 里已经内联进文本了
- 精讲册**双栏与通栏混排**，MinerU 的阅读顺序在这类页面上最容易错，跨页跨栏的解析要逐个检查
- `source.json`：每块内容来自原书哪页哪栏
- 按需处理、强制落盘，v0.1 只处理 `4.2 导数的综合应用` 一节

**需要**：Python + 耐心核对
**特点**：**风险最高的角色**，也因此最早开工。

**Plan B**：如果到 M1 结束 MinerU 还没跑通，**手工把 4.2 那一节的 kb 内容补出来**（照着 kb 结构敲），先不卡住 E 和验收。脚本可以 M3 再补——验收要的是那份 PDF，不是那个脚本。

---

### E · 出口（模板 + 编译 + skill）

**拥有**：`templates/default/`、`scripts/compile.py`、`skills/edu-handout/`

- **不从零写模板**：先找一份成熟的开源中文教辅 / 试卷模板，**先拿到一份能编译的丑模板，再往上加品牌**。顺序反过来会卡死在 ctex 配置、字体 fallback、中英混排间距里好几天。
- 组件化拆分：`main.tex`（只做 `\input`）/ `brand.tex` / `boxes.tex` / `cover.tex`
- 七个盒子环境（8.4）+ 双版开关 `\answertrue` / `\answerfalse`
- `compile.py`：`latexmk -xelatex` 一次出 `学生版.pdf` + `教师版.pdf`
- `SKILL.md`：两道闸的生产流程
- `references/53-版式语义约定.md`（第 6 节六小节原样搬）、`references/latex-规范.md`

**需要**：LaTeX 中文排版 + 审美
**特点**：和 D 并列最早开工。

**两条红线**：
1. **双版开关第一天就要就位。** 事后给几十份讲义补开关是灾难。
2. **不要 Markdown 中间态。** 大纲确认后直接写 `.tex`，`.tex` 是唯一内容真相，`outline.md` 只是一次性确认凭据。tex 必须按节拆文件，否则"局部返工"不成立。

## 2. 里程碑

按三周写，按你们实际周期等比缩放。

### M0 · 契约日（1 天，全员）
- 三个 schema 定死、提交、每人拿到 fixture
- **D 和 E 当天开始装环境**（MinerU / MiKTeX + 中文模板试编译）

### M1 · 各自跑通（约 1 周）

| | 判据 |
|---|---|
| A | 12 专题两层树全建完；8 个接口能读写假数据 |
| B | 表单能写出一个合法的 `spec.yaml` |
| C | 4.2 的两个 docx 出 LaTeX + 原图 |
| D | 4.2 精讲册出 kb（或已启动 Plan B） |
| E | 手写一份假讲义 tex，能编出双版 PDF |

**M1 判据：五个人各自都有能跑的东西，且全部是靠 fixture 跑通的。**

### M2 · 串联（约 1 周）
前端下单 → spec 落盘 → skill 读真 spec / 真 kb / 真 docx → 出 `outline.md` → 闸一确认 → 分节 tex → 编译 → 前端预览。

**M2 判据：一次完整的下单到 PDF 跑通，内容可以丑。**

### M3 · 打磨到验收（约 1 周）
品牌、配色、封面到位；4.2 讲义的内容质量过闸二。

**M3 判据：见本文开头的验收标准。**

## 3. 四条纪律

1. **每个文件有唯一 owner。** 五个人共用一个百来行的 Express 和一个 YAML，不定 owner 必冲突。跨 owner 的改动先说一声。
2. **main 永远可跑。** 每人一个分支，A 守门。
3. **别因为人多就加东西。** 账号体系、数据库、部署、多分区空壳、学生档案、出卷——这些不是"没想到"，是被"纯个人工具"和"磁盘是唯一真相"两条前提**主动砍掉**的。富余产能压在边界内（C 多跑几个专题的 docx、D 多摄取几节 kb、E 多打磨模板），不要去碰第 10 节的"不做"清单。**这是这份分工最可能失败的地方。**
4. **AI 只做编辑，不做誊抄。** C 和 E 的共同红线。

---

## 4. 关键路径

```
D（MinerU）──┐
             ├──▶ E（模板 + skill）──▶ 验收 PDF
C（docx）  ──┘
A（树 + 接口）──▶ B（前端）──▶ 下单闭环
```

**D 和 E 在关键路径上，A 和 B 不在。** 排期冲突时优先保 D 和 E；A、B 晚一两天不影响验收，D 或 E 卡住则整个 MVP 交不出东西。
