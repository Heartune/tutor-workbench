# 教培工作台 · 设计 v0.1

---

## 1. 定位与打法

### 1.1 一句话

**一个只服务你一个人的教培工作台。第一个模块是讲义生产：把 53 的内容摄取成结构化知识库，按知识点下单，AI 编辑成品牌化的 LaTeX 讲义，一份源码出学生版和教师版两个 PDF。**

### 1.2 三条被钉死的前提

| 前提 | 含义 | 被它砍掉的东西 |
|---|---|---|
| **纯个人工具** | 只有你用 | 账号体系、多租户、权限模型、计费、数据隔离 |
| **讲义站在漏斗底部** | 是成交材料，不是流量诱饵 | 批量产出、蹭热点选题、数量指标 |
| **磁盘是唯一真相** | 所有状态都是文件 | 数据库、前端本地状态、任何形式的索引缓存 |

### 1.3 讲义在生意里的位置

```
短视频（manim，已在做）  ──拉新──▶  有意向的家长 / 学生
                                        │
                                   讲义（本系统）
                                   ──成交材料──▶  签单
                                        │
                                   学生版顺手发自媒体（副产品）
```

**判据**：选题永远由"这份东西能不能拿去说服一个具体的家长"决定，不由平台热点决定。一旦开始为了"这周该发一篇"降低标准，讲义就从漏斗底部滑到了顶部，整个设计的前提失效。

### 1.4 差异化压在哪

内容以 53 为主，所以辨识度不可能来自内容本身。它只能来自三处，v0.1 必须全部保证：

1. **排版与品牌**——封面、logo、统一字体、矢量图、彩色盒子环境。家长看不懂题，但一眼能看出这和复印店的糊卷子不是一回事。
2. **讲解文字是你的**——精讲册提供结构与要点，文字由 AI 按你的讲法重写，不逐字搬运。
3. **你的补充材料**——大招、二级结论、易错点，落在教师版里。

## 2. 信息架构

### 2.1 组织轴

> **导航按资产类型分区；所有资产强制挂知识点树；树是横向索引，不是主导航。**

- **为什么导航不用树**：你日常是带着任务来的（"我要做一份讲义"），一进来面对一棵树去点是绕路。树是筛选器和关联器。
- **为什么资产必须挂树**：树是唯一能让讲义、题目、图、视频、学生薄弱点互相复用的公共坐标系。没有它，工作台就是几个工具共用一个书签栏。
- **学生分区延后**：等真的接到学生再加。学生的薄弱点标在同一棵树上，于是"这个学生弱在导数极值 → 树上这个节点有哪些现成讲义和题"是结构自然长出来的，不需要专门实现。

### 2.2 知识点树

**三层结构，强制标到第二层，第三层是自由标签。**

| 层 | 来源 | 是否强制 |
|---|---|---|
| 一层 · 专题 | 53 目录（`专题四导数及其应用`） | 强制 |
| 二层 · 小节 | 53 目录（`42导数的综合应用`、`微专题二隐零点问题`） | **强制，每个资产必须挂** |
| 三层 · 题型 / 二级结论 | 精讲册的「题型一/二」「角度一/二」、微专题名、你自己的大招 | 自由标签，多对多 |

**为什么第三层不做成树节点**：一道题可以同时是"极值点偏移"+"同构法"，一个大招会横跨多个知识点。树表达不了交叉，标签可以。而且第三层持续新增——做成标签你随手就加，做成节点你每次都要想"它该挂哪"，然后就不加了。

**两条硬规则：**

- **树存成 `knowledge-tree.yaml` 单文件，是唯一真相。** 资产在 frontmatter / spec 里用 id 引用。
- **绝不用目录层级表达树。** 讲义不存成 `handouts/导数/极值/xxx`。一份讲义常横跨三四个知识点，目录只能放一个地方，一旦如此你就会开始复制。**目录管存储，树管关系。**

前两层不需要 AI 梳理，`find` 一遍 53 的目录就能生成。

```yaml
    use: [考点清单, 题型清单]        # 讲解骨架来自精讲册
  - docx: 42导数的综合应用/5_习题WORD
  - docx: 42导数的综合应用/6_10年高考真题分类题组
  - mine: materials/大招-极值点偏移.md

audience:
  grade: 高三
  level: 中等偏上

scope:
  sections: 4
  examples: 8
  exercises: 12

template: default
status: draft                        # draft → outlined → compiled → delivered
```

**为什么用文件交接而不是剪贴板：**

1. prompt 模板留在 skill 里，前端一行 prompt 都不用管，改 prompt 不动前端。
2. spec 可存档、可复制、可 diff。做类似讲义就复制目录改两行；三个月后想知道某份讲义怎么来的，打开 spec 就知道。
3. **"讲义管理"是这个设计的免费副产品**——前端列表就是"扫描所有 `spec.yaml`"，不用另外实现。

**保留退路**：前端提供一个按钮，把 spec 渲染成一段自然语言 prompt 复制走，粘到网页版 GPT。它是备胎，不是主路。

## 5. 内容摄取：两条链路

53 每个小节下有六样东西，其中两样是可编辑文本，两样是无文本层的图片版 PDF。**这决定了必须分两条链路，不能统一入口。**

| 53 资源 | 格式 | 实测 | 链路 |
|---|---|---|---|
| `5_习题WORD` | docx | 完整文字 + 334 个 OMML 公式 + 15 张原始内嵌图 | **确定性** |
| `6_10年高考真题分类题组` | docx | 68000 字，按考点分组，含「方法」21 处、「注意」12 处 | **确定性** |
| `2_精讲册PDF` | PDF | **全页无文本层**，纯图片，双栏与通栏混排 | **识别** |
| `1_精练册PDF` | PDF | 全页无文本层；内容与 `5_习题WORD` 重复 | **不用** |
| `3_/4_ PPT` | pptx | v0.1 不用 | — |

### 5.1 确定性链路：题目与解析

**`docx → pandoc → LaTeX`，逐字保真，AI 不碰。**

- 文字与公式（OMML→LaTeX）由 pandoc 确定性转换
- 图片从 docx 解压 `word/media/*` 直接取，原始分辨率
- **AI 只做编辑，不做誊抄**：挑题（按知识点 / 难度 / 题源）、重组结构、套模板、插私货、修编译错误

> 这一条是本设计与流传的"截图喂 GPT"流程最大的分歧。那套流程让 GPT"重新出一样的题"，是因为作者只有截图。你有 docx，让 AI 重新识别题干等于主动把确定性数据降级成识别结果——而 `x³` 抄成 `x²`、题源标错这类事故，印在发出去的讲义上，你几乎无法逐题核对。

### 5.2 识别链路：讲解

**`精讲册PDF → MinerU → kb`**，四类分别处理：

| MinerU 输出 | 类型名 | 处理方式 | 理由 |
|---|---|---|---|
| 文字讲解 | `text` | AI **理解要点后用你的话重写** | OCR 小错不入册；且这是差异化落点 |
| 公式 | `equation`（行间，独立块）/ `inline_equation`（行内，span） | **直接用**，MinerU 已输出 LaTeX（`text_format: "latex"`） | 不让 AI 重写公式 |
| 表格 | `table`，`table_body` 是 **HTML** | 脚本 `html_table_to_latex.py` **确定性转换**，AI 只调样式不碰数据 | 比让 AI 看图重建可靠 |
| 图 | `image`，`img_path` 指向切好的图片文件 | **直接用**；需反复复用的原理图才 TikZ 重画 | 保真、零成本 |

**行内公式要读 `middle.json` 的 span 层**，`content_list.json` 里已经内联进文本了。

**版面提醒**：精讲册**双栏与通栏混排**（考点清单双栏，部分题型讲解通栏），MinerU 的阅读顺序在这类页面上最容易错。跨页/跨栏的解析要检查是否被拼接错乱。

### 5.3 TikZ 的位置

**保留但不默认。** 判据是"这张图会不会被反复用"：

- 一道题的示意图 → 用原图
- "导数与单调性的对应关系""三次函数根的情况"这类要在很多份讲义里复用的原理图 → TikZ 画成矢量，存进 `kb/**/figures/` 当共享资产，同样挂知识点树，画一次用一年

**不要一上来就全部 TikZ 重画**：AI 画 TikZ 极容易在坐标、比例、标注位置上出错，你要逐张核对，比用原图慢十倍。

### 5.4 按需处理，强制落盘

53 全套 305 个文件、334 MB。**不要先把全书跑一遍 MinerU。**

- **按需**：做哪一节讲义就处理哪一节
- **强制落盘**：产物必须写进 `kb/` 的标准结构并挂树，下次直接读 kb，不再碰 PDF
- 结果：**用着用着 kb 就长满了，而且长出来的都是你真正用过的部分**

反面是"等我把 53 处理完再开始做讲义"——那会变成拖延，而且处理的大部分是你根本用不到的章节。

## 6. 53 版式语义约定

MinerU 输出的是纯文本块，**所有颜色、图标、标签底色一律丢失**。这一节把 53 的视觉标记翻译成可用关键词恢复的语义，`skills/edu-handout/references/53-版式语义约定.md` 原样放这份内容。

### 6.1 专题级（每个专题首页）

| 视觉标记 | 语义 | 关键词锚点 |
|---|---|---|
| 页顶蓝色圆角横幅 + 「学·即清」印章 | 专题标题 | `专题N` |
| 蓝底圆角标题条 + 剪贴板图标 | 考情板块开始 | `考情清单` |
| 五列表格：考点 / 20—24年考频 / 真题示例 / 考向 / 核心素养 | 命题统计 | 表头 |
| 灰色小标签 + 浅蓝底框 | 专题命题特征概述 | `命题形式` |

### 6.2 小节级 · 精讲册

| 视觉标记 | 语义 | 关键词锚点 |
|---|---|---|
| 居中大号黑体 `4.2 导数的综合应用` | 小节标题 | 编号+标题 |
| 蓝底圆角标题条 + 图标 | **知识梳理板块开始** | `考点清单` |
| 橙底白字方标签 + 黑体标题 | 一级知识条目 | `考点1` `考点2` |
| 黑体数字标题 `1.函数的极值` | 二级知识条目 | `N.` 开头 |
| 细线表格 | 条件—结论对照 / 变化情况表 | — |
| 蓝色左竖线标签 + 蓝色圆角虚框 + 楷体 | **补充结论（延伸/超纲）** | `知识拓展` |
| 三角警示图标 + 楷体（行内或独立段） | **易错警示** | `注意` |
| 蓝色居中标题 | 小测（约 5 题） | `即练即清` |
| 方框 + 居中标题 | 小测答案 | `即练即清答案` |
| 蓝底圆角标题条 + 图标 | **方法与题型板块开始** | `题型清单` |
| 橙底白字方标签 + 黑体标题 | 题型分类 | `题型一` `题型二` |
| 蓝色圆角边框标签 | 例题 | `典例1` `典例2` |
| 紧随典例的括号小字 | **题源** | `(2025届清华附中开学考试,19节选)` |
| 蓝色黑体二字 | 解答开始 | `解析` |
| 蓝色小图标 + 蓝色黑体 | **大招 / 二级结论——全书最值钱的部分** | `方法总结` |
| 蓝底标签 | 配套变式 | `变式训练1-1` |
| 蓝色小圆角标签，紧随变式训练 | 变式类型 | `关键元素变式` |
| 右上角箭头 + 小字 | 与学生用书的页码对应 | `学生用书P43` |

### 6.3 微专题（结构与小节不同）

| 视觉标记 | 语义 | 关键词锚点 |
|---|---|---|
| 蓝色三角 + 横幅标题 | 微专题标题 | `微专题二 隐零点问题` |
| 开篇无标签导语 + `(1)~(6)` 条 | **方法总纲**（相当于该微专题的大招集合） | 位于标题正下方，无标签 |
| 黑体标题 | 分类（替代「题型一/二」） | `角度一` `角度二` |
| 黑体 | 解析内的步骤划分 | `第一步` `第二步` `第三步` |
| **蓝色行内批注**，如「虚设零点」「用代换法解决隐零点问题」 | **解题关键点提示** | **无关键词** |

### 6.4 精练册 / 习题WORD

| 标记 | 语义 |
|---|---|
| 板块标题 | `五年高考` / `三年模拟` |
| `1.(2023北京,20,15分,中)` | 题号 + 题源（年份 / 地区 / 题号 / 分值 / **难度：易·中·难**） |
| `解析` | 解答 |

### 6.5 十年高考 WORD

| 标记 | 语义 |
|---|---|
| `考点1 导数与函数的单调性` | 按考点分组 |
| `答案　C` | 客观题答案 |
| `解析` | 解答 |
| 正文中的 `方法` / `注意` / `素养` | **这些语义在 docx 里是纯文本，可确定性抽取，无需 OCR** |

### 6.6 一个救不回来的标记

**6.3 最后一行的「蓝色行内批注」是唯一没有关键词锚点的标记。** 它嵌在解析的行文中间，仅靠蓝色区分，MinerU 会把它当普通文字混进正文——结果是解析里突然冒出「虚设零点」这样一个没有语法连接的短语。

**skill 必须写明这条**：解析文本中出现的、与上下文没有语法衔接的四到十字短语，很可能是被吞掉的行内批注，应识别出来转成边注（`\marginnote`）而不是留在正文里。这类批注恰恰是解题关键点，价值很高，值得单独处理。

## 7. 生产流程：两道闸

```
spec.yaml
   │
   ├─ Stage 1  备料：按需 ingest（kb 已有则跳过）
   │
   ├─ Stage 2  产出 outline.md
   │              ┌───────────────────┐
   │              │  ▣ 闸一 · 你确认     │   ← 唯一强制确认点
   │              └───────────────────┘
   │
   ├─ Stage 3  写 sections/*.tex
   │            表格走脚本 / 公式用 MinerU 输出 / 图从 docx 与 MinerU 取
   │            按第 6 节把语义标记还原成盒子环境
   │
   ├─ Stage 4  latexmk 编译，报错自己修，出双版 PDF
   │
   └─ Stage 5    ┌───────────────────┐
                 │  ▣ 闸二 · 你看 PDF   │   ← 不满意则局部返工
                 └───────────────────┘
```

### 闸一 · 选题与大纲

skill 先**只**产出 `outline.md`：分几节、每节讲什么、选了哪些题（标到「53 · 4.2 · 变式训练 1-1」或「2023北京 T20」）、难度分布、你的补充材料插在哪。几十行，三十秒扫完。

**这道闸必须有，因为最贵的错误全部发生在这一层**：选错题、难度跑偏、覆盖不对、私货没用上。在大纲阶段改是改两行字；等 tex 和图都做完再发现，是重跑一整份。

### 闸二 · 看 PDF

翻一遍。不满意的地方**局部返工**：只重做第三节、只换某道题，不动其他部分。

### 两条支撑规则

- **不要 Markdown 中间态。** 大纲确认后直接写 `.tex`。若先生成 md 再转 tex，md 和 tex 会变成两份真相——你改了 tex，下次返工时 AI 读到的是过期的 md。**`.tex` 是唯一的内容真相，`outline.md` 只是一次性确认凭据。**
- **tex 必须按节拆文件**，`main.tex` 只做 `\input`。这是"局部返工"能成立的前提，否则每次改动都要 AI 重吐整个文件，又慢又容易改坏别处。

### 溯源

教师版每个引用块的页边标注来源（`53 · 4.2 · P46 考点2`），便于你抽查。学生版不显示。

## 8. 模板与品牌

### 8.1 策略

**单套讲义模板起步，但第一天就组件化拆分；不从零写，找一份成熟的开源中文教辅 / 试卷模板打底，再按品牌改造。**

- **为什么先只做一套**：现在只有"讲义"一种产物。等要做试卷、作业单、家长报告了再加，那时是**复用**（换封面、换题号样式）而非重写——前提是封面、页眉页脚、题目环境、答案环境、配色变量第一天就拆成了独立文件。
- **为什么不从零写**：中文 LaTeX 的坑（ctex 配置、字体 fallback、中英混排间距、题号自动化）从零踩要好几天，成熟模板早解决了。**先拿一份能编译的丑模板，再往上加品牌**；顺序反过来会卡死在编译报错里。

### 8.2 一份源码，两个 PDF

```latex
% main.tex 顶部
\answertrue    % 教师版：题目 + 完整解析 + 方法总结 + 你的大招 + 易错提示 + 溯源标注
\answerfalse   % 学生版：题目 + 留白
```

`compile.py` 一次跑出 `out/学生版.pdf` 和 `out/教师版.pdf`。

四个理由：上课你要看解析而学生不能有；你的私货有了明确的存放位置；发自媒体的是学生版；实现成本极低。**但必须一开始就定**——事后给几十份讲义补开关是灾难。

### 8.3 配色：浅底 + 彩虹

底色是浅的，彩虹用在**语义区分**上——七个盒子环境各占一个色相，读者靠颜色就能分清"这是补充结论"还是"这是易错警示"。这既好看，又是功能性的；比 53 原书全篇一种蓝要清楚。

**中性色**

| 项 | 值 |
|---|---|
| 纸面底色 | `#FDFDFB` |
| 正文 | `#1A1A1A` |
| 次级文字 / 边注 | `#6B7280` |
| 分隔线 | `#E5E5E0` |

**彩虹色带**（每个盒子 = 一个色相；底色统一用该色 8% 透明度，边框用本色）

| 色 | 值 | 绑定的环境 | 对应 53 |
|---|---|---|---|
| 红 | `#E5484D` | `注意` | ⚠ 注意 |
| 橙 | `#E8862A` | `典例` · 题号 | 典例 N |
| 黄 | `#D9A404` | `即练即清` | 即练即清 |
| 绿 | `#3FA65C` | **`方法总结`** | 🔧 方法总结 |
| 青 | `#17A2A2` | `变式` | 变式训练 N-N |
| 蓝 | `#2D7FF9` | `知识拓展` | 知识拓展 |
| 紫 | `#8B5CF6` | `考情` | 考情清单 / 命题形式 |

**用色纪律**（否则彩虹会变成花）：

- 正文、公式、表格线一律中性色，**彩色只出现在盒子边框、标签底、题号上**
- 一页里出现的色相不超过三种；同一节内不重复使用同一色相做不同语义
- 封面用一条七色细带（横贯页宽 4pt），其余留白
- **学生版的方法总结整块隐藏**，所以学生版实际见到的颜色更少、更干净

### 8.4 盒子环境（`boxes.tex`）

| 环境 | 色 | 用于 | 学生版 |
|---|---|---|---|
| `\begin{知识拓展}` | 蓝 | 补充结论、延伸 | 保留 |
| `\begin{注意}` | 红 | 易错警示 | 保留 |
| `\begin{方法总结}` | 绿 | **你的大招落点** | **隐藏** |
| `\begin{典例}` | 橙 | 例题（自动带题源） | 保留（解析随开关） |
| `\begin{变式}` | 青 | 变式训练 | 保留（解析随开关） |
| `\begin{即练即清}` | 黄 | 小测 | 保留（答案随开关） |
| `\begin{考情}` | 紫 | 考情表、命题形式 | 保留 |
| `\marginnote{}` | 灰 | 6.6 救回来的行内批注、溯源标注 | 隐藏 |

### 8.5 品牌占位

替换时**只改 `templates/default/brand.tex`**：

| 项 | 占位值 |
|---|---|
| 名称 | **函舟** |
| 释义 | 函数之舟；占位用，随时换成你的账号名 |
| logo | 一道彩虹色抛物线弧，弧下一个舟形剪影，浅底透明背景，`assets/logo.svg` |
| 配色 | 见 8.3 |
| 中文字体 | 思源宋体（正文）/ 思源黑体（标题、标签） |
| 数学字体 | Latin Modern Math |
| 封面 | 浅底 + 七色细带 + 大字标题 + 知识点路径 + logo，其余大量留白 |

**做视频时如果已有配色或账号名，应直接沿用**——视频和讲义看起来是同一个人做的，这个一致性本身就是专业度信号。

## 9. 技术栈与前端

### 9.1 栈

| 层 | 选择 | 理由 |
|---|---|---|
| 前端 | **Vite + Vue 3 + TypeScript** | 壳会长到四五个模块；组件化是为三个月后的你 |
| 后端 | **Express**，约 8 个接口，百来行 | 只做"列目录、读写文件、存图片、吐 PDF" |
| 数据 | **YAML 文件** | 无数据库。磁盘是唯一真相 |
| PDF 预览 | `<iframe>` + 浏览器内置阅读器 | 省掉 pdf.js 一整坨 |
| 脚本 | Python（本机已有 PyMuPDF / python-docx / pdfplumber） | 被后端 `spawn` 调用，**不把后端换成 Python** |
| 编译 | MiKTeX（已装：`D:\MiKTeX`），`latexmk -xelatex` | — |
| 待装 | `pandoc`、MinerU | — |

### 9.2 接口

```
GET   /api/tree                        知识点树 + 标签池
GET   /api/handouts                    扫描 handouts/*/spec.yaml，返回列表与状态
GET   /api/handouts/:id                spec + outline + 产物清单
POST  /api/handouts                    写一个新的 spec.yaml
PUT   /api/handouts/:id/spec           改 spec
POST  /api/handouts/:id/assets         上传素材图，落进 images/
GET   /api/handouts/:id/pdf/:variant   学生版 / 教师版
GET   /api/kb                          已落盘的 kb 节点（哪些章节处理过了）
```

### 9.3 前端 v0.1 的页面

**只有讲义一个分区，其他分区连入口都不出现。**

```
┌──────────────────────────────────────────────┐
│ ▬▬▬▬▬▬▬  函舟工作台                （七色细带）│
├───────────────┬──────────────────────────────┤
│ 讲义列表       │  spec 表单 / PDF 预览          │
│ ─────────     │                              │
│ ● 导数综合应用  │  知识点树选择器（二层，强制）      │
│   compiled    │  标签（多选，可新建）             │
│ ○ 隐零点微专题  │  题源勾选（kb / docx / 我的材料）  │
│   draft       │  受众、篇幅、模板                │
│ + 新建讲义     │  ────────────                │
│               │  [创建]  [复制为 prompt]        │
└───────────────┴──────────────────────────────┘
```

**为什么不先把四个分区的空壳摆出来**：壳的形状由"模块之间共享什么"决定，而只有一个模块时你看不出该共享什么。先摆空分区等于凭想象定结构，第二个模块进来多半要推倒。

**视觉投入可以低，但它必须真的被用起来。** 前端的核心价值是那个高频循环——生成 → 编译 → 看排版丑不丑 → 改 → 再编译。把"看"变成刷新网页，比来回开 PDF 阅读器省事得多。

## 10. v0.1 边界与验收

### 做

| 模块 | v0.1 范围 |
|---|---|
| 知识点树 | 12 专题的**前两层全建**（`find` 一遍即可）；第三层标签只填导数专题 |
| kb | **只处理 `4.2 导数的综合应用`**，docx + 精讲册各一份，验证两条链路 |
| 前端 | 讲义分区：树选择器、下单表单、列表、PDF 预览、素材上传 |
| skill | `outline.md` → 分节 tex → 编译 → 双版 PDF，两道闸 |
| 模板 | 一套，组件化拆好，七个盒子环境，双版开关就位，品牌用占位 |
| 脚本 | `build_tree` / `ingest_docx` / `ingest_pdf` / `html_table_to_latex` / `compile` |

### 不做

学生档案与计划、录音与复盘、出卷、PPT、眼镜、题库分区、视频分区、账号、部署、移动端。

### 验收标准

> **用这套东西做出一份《4.2 导数的综合应用》讲义，学生版 + 教师版两个 PDF，你自己看了愿意把它发给一个真实家长。**

不是"功能都实现了"，是"**产出物拿得出手**"。这个项目的赌注是用作品换信任，作品不够格，功能再全也没意义。

### 建议的实施顺序

1. `build_tree.py` → `knowledge-tree.yaml`（最快见效，且是所有东西的地基）
2. `ingest_docx.py` + pandoc，跑通 4.2 的习题 docx → LaTeX + 图
3. `templates/default/` 打底，**先保证空模板能 xelatex 编译**，再加品牌与盒子
4. MinerU 装好，`ingest_pdf.py` 跑通 4.2 精讲册 → kb
5. `edu-handout` skill，两道闸，把第 6 节写进 references
6. Express + Vue 前端
7. 做出第一份讲义，对照验收标准

前 5 步做完其实已经能出讲义了（命令行下单）；第 6 步是把下单这一步从打字变成点树。

## 11. 远期设想（v0.1 之外）

以下来自最初的构想，**没有被否定，只是排在讲义之后**。等讲义模块跑通、且你真的接到学生，再逐条重新评估。

### 11.1 原始痛点清单

| 痛点 | 现状 | 设想的解法 | 当前状态 |
|---|---|---|---|
| 备课耗时 | 每节课手动准备讲义 / PPT | 按计划 + 教材自动生成 | **v0.1 正在做（讲义部分）** |
| 遇到不熟的科目 / 题目 | 只能拒单或课前恶补 | 眼镜实时提示解法 | 推迟 |
| 课后复盘靠手写 | 现在基本不写 | 录音自动生成四板块复盘 | 推迟 |
| 学生情况没沉淀 | 都在老师脑子里 | 结构化学生画像 | 推迟（树已为它预留位置） |
| 出题 / 出卷麻烦 | 翻书、拼 Word、排版乱 | 一键出卷，LaTeX 导出 PDF | 推迟（模板已为它组件化） |

### 11.2 AI 眼镜

设想中眼镜承担四个角色：**录音器**（全程录音、老师零操作）、**提词器**（讲稿直接在镜片上念）、**实时兜底**（不懂的题眼镜给解法思路）、**摸鱼位**。

保留但排在最后，两个原因：

- **实时兜底既是最大的价值主张也是最大的风险点**——AI 讲错一道题，老师当场无法判断。
- 更根本的是，"一次录音喂出四件事"这个模型建立在**音频是唯一数据源**上。数学课的关键信息在纸面和板书上，嘴里说的是"这里我们设它为 t""看这个式子"。这个假设需要单独验证，不能默认成立。

### 11.3 复盘

四板块固定模板：**上课内容 / 课堂表现 / 待改进与提升计划 / 课后作业**，逐课累积成可对比的时间序列。

定位需要修正：它**不是效率工具，是信任凭证**——让家长看见"这位老师在用 AI 认真记录每一节课"，支撑高于市价的定价。所以它的成功标准是"家长看了觉得专业、愿意续费"，不是"内容还原有多准"。这一点会显著改变它的设计，做之前要重新想清楚。

### 11.4 数据闭环

```
录音 → 转写 → 知识点抽取 → 学生画像（薄弱点 / 掌握度 / 进度）
                                    ↓
                        反哺下一次的计划 与 出题范围
```

**这个闭环的可行性完全取决于第 2.2 节那棵知识点树。** 讲义、题目、图、视频、学生薄弱点全部挂在同一棵树上，闭环才是结构自然长出来的；否则它永远只是一张图。这也是为什么树在 v0.1 就要建好，哪怕当前只有讲义在用它。
