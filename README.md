# 函舟工作台 · tutor-workbench

一个只服务一个人的教培工作台。v0.1 只做讲义生产：把《5·3》北京版数学的配套资源摄取成结构化知识库，按知识点下单，AI 编辑成品牌化的 LaTeX 讲义，一份源码出学生版和教师版两个 PDF。

设计文档见 [`../教培工作台-思路整理.md`](../教培工作台-思路整理.md)。

## 架构与技术栈

本项目是一个纯本地的单人工具，**磁盘是唯一真相**——没有数据库、没有账号体系、没有任何索引缓存，全部状态就是仓库里的 YAML、Markdown、LaTeX 和 PDF 文件。前端用 Vite + Vue 3 + TypeScript 写一个薄壳，后端是百来行的 Express（约 8 个接口，只负责列目录、读写文件、存图片、吐 PDF），PDF 预览直接交给 `<iframe>` 里的浏览器内置阅读器。真正干活的是被后端 `spawn` 调用的一组 Python 脚本（PyMuPDF / python-docx / pandoc / MinerU）和本机 MiKTeX 的 `latexmk -xelatex`；后端本身不承担计算，也不因此换成 Python。前端与 AI 之间靠文件交接：前端只写 `spec.yaml` 任务单，skill 只读 `spec.yaml`，prompt 模板全部留在 skill 里，前端一行 prompt 都不管。所有资产（讲义、题目、图、日后的视频与学生薄弱点）强制挂到 `knowledge-tree.yaml` 这棵三层知识点树上——它是横向索引和复用的公共坐标系，不是主导航；导航按资产类型分区。

## 核心功能

围绕"下单 → 出讲义"这一条链路展开。**内容摄取分两条链路**：习题 WORD 走确定性链路，`docx → pandoc → LaTeX` 逐字保真、图片从 `word/media/` 原样取出，AI 只做挑题、重组和插私货，绝不重新誊抄题干；无文本层的精讲册 PDF 走识别链路，经 MinerU 后分四类处理——文字由 AI 理解要点后用自己的话重写（这也是差异化的落点），公式直接用 MinerU 输出的 LaTeX，表格由脚本把 HTML 确定性转成 `tabular`，图直接引用切好的文件。摄取按需进行、强制落盘进 `kb/` 并挂树，用着用着知识库就长满，且长出来的都是真正用过的部分。**生产流程有两道强制闸**：先只产出 `outline.md`（分几节、选了哪些题、难度分布、补充材料插在哪）供确认——最贵的错误全部发生在选题这一层；确认后直接写分节的 `.tex`（不留 Markdown 中间态，`.tex` 是唯一内容真相），编译、看 PDF，不满意则只重做某一节。**模板一套但第一天就组件化拆分**，品牌变量集中在 `brand.tex`，七个彩色盒子环境按语义区分色相，靠 `\answertrue/\answerfalse` 一个开关从同一份源码编出教师版（含完整解析、方法总结、大招、溯源标注）和学生版（题目与留白，方法总结整块隐藏）。讲义管理是这套设计的免费副产品——列表就是扫描所有 `spec.yaml`。
